# 用户登录状态控制

服务端：除了在登录、注销两表中存储 SessionID 以外无状态。

客户端：通过 JWT 令牌进行身份验证。

### 登录流程

1. 客户端用户输入账号、密码，点击登录按钮
2. 客户端请求 LoginSessionSalt、Salt
3. 客户端运算 R=Hash(LoginSessionSalt+Hash(Password+Salt))
4. 客户端立即进行登录请求，LoginToken 字段为 LoginSessionSalt+R
4. 服务器取 LoginSessionSalt 元信息，校验合法性，如果通过：
5. 服务器拼接 LoginSessionSalt 与密码加盐哈希，与前端传回值进行比较，如果通过：
6. 验证成功，LoginSessionSalt 中的 SessionSalt 被记录
7. 服务器签发 JWT 令牌，令牌 jti 字段等于 SessionSalt

LoginSessionSalt 组成：T...S...H...

- S - SessionID：用户登录会话的特征值，高熵随机数
- T - 过期时间：该 LoginSessionSalt 的过期时间（UNIX时间戳）
- H - 服务端签名：S+T 两个部分的签名，使用服务器私钥

客户端 LoginToken 组成说明：

LoginToken = LoginSessionSalt + Hash(LoginSessionSalt + Hash(Password+Salt))

- LoginSessionSalt - 为使服务端相对无状态，需要返回明文的已签发 LoginSessionSalt
- Hash(... - 第一层哈希，防止中间人拿到原始 Hash(Password+Salt) 进行重放攻击
- LoginSessionSalt+... - LoginSessionSalt 包含 SessionID，本身具备高熵特性，可以直接作为盐使用
- Hash(Password+Salt) - 第二层哈希，服务器保存的值
- Salt - 注册时使用的盐，防止服务器泄露密码被批量攻击

### 防范重放攻击、竞争登录攻击

一旦用户登录成功，SessionID 在服务端被记录，具有相同 SessionID 的 LoginSessionSalt 即刻失效

若用户登录因为网络原因被阻塞，签发的 LoginSessionSalt 会在很短的时间（不超过三十秒）过期，避免 LoginSessionSalt 被泄露而被竞争登录攻击

### 注销流程

1. 客户端携带 JWT 令牌请求注销
2. 服务器记录 SessionID 至注销表
3. JWT 令牌失效，用户需重新进行登录流程，申领不同的 SessionSalt 并拿到对应 JWT

### 密码修改流程

使用旧密码更新：
- 由于使用 JWT 令牌，因此需要在同一个请求内重新验证用户身份
1. 客户端依照登录方法生成 loginToken，返回为 verifyData
2. 客户端生成盐，与新密码一起返回
3. 服务端验证合法性，修改用户模型

该流程仍有以下弱点：
- 修改密码流程新密码原始加盐哈希暴露，可被重放攻击
- 为了保护原始密码，新密码盐不得不由不可信前端生成
